## #911 cloud-init failure carries no diagnostics

### The problem

When `cloud-init status --wait` exits non-zero in a new VM, the harness
raises `cloud-init failed in <vm>: <stderr>`. cloud-init reports on
stdout, so the message is usually empty and the rc is never shown. Four
CI failures so far, one with `Error: Failed to connect to lxd-agent`; the
cause is unknown. The issue asks for rc, stdout, stderr,
`cloud-init status --long` and the tail of `/var/log/cloud-init.log` in
the error, and also that degraded (rc 2) is only a warning and a lost
lxd-agent is retried once.

### Where

- `tests/robot/resources/microceph_harness.py`: `_launch_vm_instance`
  (line 1636, called from `launch_outer_test_vm` at 1622); the wait at
  1677 and the bare raise at 1679. `_exec` (189) is the non-raising helper.
- `tests/robot/resources/test_vm_launch_failure.py`: `exec_lxc` stub
  (line 43), `test_readiness_failure_tears_down_only_requested_vm` (61).
- `tests/robot/resources/test_harness_helpers.py`: pure-helper tests;
  `_Res` is defined at line 2147.
- CI gate: `Checks`, job `Run Unit tests` (pytest over `tests/robot/resources`).

### First job

Make the `exec_lxc` stub answer the `--wait` call with `status: error` on
stdout and assert that text is in the raised message. It fails on main.

### Definition of done

- [ ] The failure message carries the wait's rc, stdout and stderr,
      `cloud-init status --long` and the cloud-init log tail.
- [ ] The prefix `cloud-init failed in <vm>:` is unchanged.
- [ ] Tests cover the new message, and `test_vm_launch_failure.py` still
      rejects unexpected commands.
- [ ] Green: `python3 -m pytest -q tests/robot/resources`,
      `./clinic dryrun`, `tox -e robot -- --test-suite unit-tests`.
- [ ] Commit title `test: <summary>`. `Fixes #911` only if degraded and
      the lxd-agent retry are handled too; otherwise `Related: #911`.

## #909 apt-get update rc 100 (index desync) is not retried

### The problem

`apt-get update` exits 100 when a mirror serves an index out of step with
its Release file (`Hash Sum mismatch`, `File has unexpected size`), even
with `Acquire::Retries=3`. `_is_transient_apt_stall` only accepts rc 124
with empty stdout, so this fails the suite at once. The issue also covers
an unretried `add-apt-repository` (Launchpad tracebacks), which open PR
#863 bounds but only retries on rc 124. Expected: a mirror hiccup is
retried or tolerated, and exhaustion still fails with the `kind=apt`
annotation.

### Where

- `microceph_harness.py`: `_retry_transient` (541), `_is_transient_apt_stall`
  (613), `_run_apt` (645), `apt_update` (671), `apt_install` (679).
- `test_harness_helpers.py`: `test_is_transient_apt_stall` (3010), its
  parameter list just above, including an rc 100 `404  Not Found` case
  marked non-transient (3006).
- PR #863 (a large SMB PR); only its `add_apt_repository` change in
  `microceph_harness.py` matters here.
- CI gate: as for #911.

### First job

Add rc 100 `Hash Sum mismatch` and `File has unexpected size` results to
the transient-predicate tests; they come back non-transient on main.

### Definition of done

- [ ] An `apt-get update` rc 100 with index-desync stderr is retried or
      tolerated; the PR says which and why.
- [ ] rc 100 with a 404, or `Unable to locate package`, still fails at once.
- [ ] Exhausted retries still fail with the `kind=apt` annotation.
- [ ] Tests for each case; same green checks as #911.
- [ ] Commit title `test: <summary>`. `Fixes #909` only if the thread
      agrees the scope closes it; otherwise `Related: #909`.

## Watch out

- `apt_install` and PR #863's `add_apt_repository` share `_run_apt`;
  changing `_is_transient_apt_stall` changes them too.
- `Failed to fetch` as a retry marker would make the existing 404 case
  transient.
- `test_vm_launch_failure.py` has a strict `lxc exec` stub: any new
  command in `_launch_vm_instance` fails it until the stub knows it.
- `AGENTS.md`, "Library rules": class name equals module name, keep
  `ROBOT_LIBRARY_SCOPE`, no `BuiltIn().run_keyword`, pure helpers are
  `@staticmethod`, the result field is `rc`. Breaking these silently
  drops keywords.
- Tests leave `microceph-orch/**/__pycache__/` untracked; add files by name.
- Question (#909): retry, or tolerate rc 100 and let `apt_install` decide?
